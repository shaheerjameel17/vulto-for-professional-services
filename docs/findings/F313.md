### F313 — the notification engine's prescribed folder violates the A003-T52 gate

**Found while:** Codex tracing the Stage 25 brief before writing product code, 26 September 2026 (stage report `8a8c9e8`); ruled by the reviewer the same day.

The Stage 25 brief placed the notification delivery engine in a new `services/api/src/notifications/` folder and required that only `services/api/src/mutations/pipeline.ts` change under `mutations/`. `scripts/arch-check.mjs` (A003-T52, in `pnpm verify`) allows `graph/store` writes only from `services/api/src/mutations` and the graph module's own founding and membership code, so the engine cannot live outside `mutations/`; and the brief's own read-state and reminder mutations (Do items 4 and 5) also live there, so the pipeline-only boundary contradicted the brief itself. The reviewer had not run the gate against the prescribed shape (the F304 lesson again). Reproduced in a scratch tree by the builder and re-verified by the reviewer: a store-importing file under `mutations/` passes `arch:check`, under `jobs/` it fails the write rule, and under `notifications/` it fails both.

**Files:** `scripts/arch-check.mjs`, `services/api/src/mutations/`, `docs/Claude_Code_Build_Prompt.md`

**Ruling.** **Closed 26 September 2026 by ruling.** The engine is `services/api/src/mutations/notification-delivery.ts`, beside `revenue-gap-alert.ts`, `timesheet-anomaly.ts` and `utilization-snapshot.ts`. The boundary that protects G03 is restated as what it was always for: no existing source feature's mutation file changes; the diff under `mutations/` is `pipeline.ts` (the hook), the new Notification files, and additive registrations. The gate is unchanged. Lesson recorded in the reviewer role: before ruling or briefing a location, run the gate against a scratch file at that exact path with those exact imports.
