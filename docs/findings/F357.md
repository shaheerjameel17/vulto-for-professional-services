### F357 — `SyncEngine.mutate` durably queues a Tier 1/online-only mutation's plaintext arguments before ever contacting the server

**Found while:** Codex's UI-2 pre-build trace, 27 September 2026, tracing the compensation write path (Do item 3) before writing product code.

`packages/schema/src/mutations/employee.ts` declares `employeeSetCompensation` as `tier: 1, onlineOnly: true`, and its optimistic mutator (`packages/graph/src/mutators/foundation.ts`) writes nothing to the cache, by design ("never applied to the cache, because a protected value never reaches one"). But `sync-client/engine.ts`'s `mutate()` only refuses a queued write "when not online" (its own comment claims "A protected or online-only mutation is never queued (A003-T63)", which is not what the code does): once the connectivity check passes, `mutate()` proceeds through the same path as any Tier 0 mutation — it calls `this.#outbox.append({ mutationId, name, args, undo, createdAt: now })` unconditionally, and `Outbox.append` inserts `args_json` (`JSON.stringify(args)`, the plaintext compensation amount, frequency and currency) into a real, durable SQLite `outbox` table. If the subsequent upload is interrupted before `drain()` removes the row, the plaintext value sits on the device disk — directly contradicting `VRS-F002`'s own Security Considerations ("Compensation is fetched, never cached... held in memory for the session and are never written to the device") and A003-T56. A synthetic, isolated reproduction (fresh in-memory database, forced upload failure) confirmed the row's presence rather than inferring the leak from the code alone.

**Files:** `packages/graph/src/sync-client/engine.ts`, `packages/graph/src/sync-client/outbox.ts`, `packages/schema/src/mutations/employee.ts`

**Ruling.** **Closed 27 September 2026 by ruling.** The engine already has the correct precedent for this exact shape: `protectedRead` (same file, under "Protected values: memory only") talks to the API directly and holds its result only in the in-memory `#protected` cache, never the outbox. Add a symmetric `protectedMutate(name, args)` beside it: it refuses immediately (`requires-connection`) unless online, then calls `this.#options.api.applyMutations([{ mutation_id, name, args }])` directly and awaits the result inline — no `outbox.append`, no `drain()`, nothing durable at any point. Map the single outcome to `MutateOutcome` the same way `#drainOnce` already does (rejected → the outcome's reason; otherwise accepted). Expose it on `GraphClient` next to `protectedRead`. Harden `mutate()` itself with a guard refusing any mutation whose definition is `tier > 0` or `onlineOnly` (a mutation name that should never reach the outbox in the first place), so a future Tier 1/online-only mutation cannot recreate this defect by calling the wrong method. `employee.setCompensation` is the first and, at this writing, only caller of `protectedMutate`.
