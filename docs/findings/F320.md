### F320 — the spec's listForUser filter parameter is undefined

**Found while:** Codex implementing Stage 25 Do item 7, 26 September 2026 (partial pushed as `d6a100f`); ruled by the reviewer the same day.

Do item 7 of the Stage 25 brief required `notificationListForUser(database, filter?)`, copying the spec's `notification.listForUser(userId, filter?)`, but neither the spec (`VPS-F003`'s API contract) nor the brief defines what `filter` is or does: its type and behavior appear nowhere, and the Inbox's read is fully covered by the three groups (`needsYou`, `today`, `earlier`).

**Files:** `docs/Vulto_Specs/VPS-F003_Notification_and_Alert_Center.md`, `packages/graph/src/queries/notifications.ts`

**Ruling.** **Closed 26 September 2026 by ruling.** Not built. `notificationListForUser(database)` takes neither a `filter` nor a user id (the audience-filtered device cache is the scoping, as for search, F300). A later stage that has a consumer for a filter defines it with that consumer. The spec gets a Decisions Recorded entry. Lesson: a copied contract parameter needs a definition or is dropped.
