### F240 — Assignment cancellation omits the mandatory state-transition base version

Raised 23 September 2026 while resuming Stage 13 (`RST-41`) on F239's ruling, before any product code was written.

**The conflict.** Stage 13 Do item 1 and `VRS-F005`'s API contract both specify `assignment.cancel(assignmentId) -> { success }`. Cancellation changes the Assignment's state from `Active` to `Canceled`; `VRS-F005` names those values in Assignment's schema, and the registry uses the fixed lifecycle policy for this node type. `VPS-A003` A003-T54 requires every state-transition mutation to carry the base `version` the decision was made against and requires the server to reject `stale-state` when that version has changed. The shared mutation envelope carries no implicit base version.

This is the exact contract gap F223 resolved for `entity.deactivate` and F228 resolved for `holiday.cancel`, `calendar.update`, `pattern.set` and `pattern.clear`.

**Closed by founder-delegated decision, 23 September 2026, on F223/F228's own reading of A003-T54.** The contract gains a required `expectedVersion`: `assignment.cancel(assignmentId, expectedVersion) -> { success }`. `validate()` checks it first — `stale-state` before anything else — then transitions `status` from `Active` to `Canceled`, the same version-first ordering F223 established for `entity.deactivate` and F228 established for `holiday.cancel`/`calendar.update`/`pattern.set`/`pattern.clear`. `assignment.create` and `assignment.update` need no version argument: `create` has none to check against, and `update` never touches `status` — the same ordinary-field-write exemption F228 gave `holiday.confirm`. The optimistic handler mirrors `holidayCancel`'s exact shape in `packages/graph/src/mutators/foundation.ts`: compare the cached Assignment's version to `expectedVersion`, throw `OptimisticRejection("stale-state")` on mismatch, otherwise write `status: "Canceled"` locally against the checked version. `VRS-F005`'s API contract and Stage 13's Do items 1 and 7 are both corrected to the new signature and behavior.

**Status: closed.** Stage 13 is unblocked.
