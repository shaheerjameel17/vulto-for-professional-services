### F285 — `requires_skill` declares no governing partition for either of its two tier-split endpoints

Raised 25 September 2026, checking `VRS-F013` directly against the code before writing its Stage 21 brief. `requires_skill` pairs Skill against five node types — Project, OpenRole, Pitch, CareerMilestone, Requisition — and declares no `governingPartitions` entry at all. Two of those five, Pitch and Requisition, are tier-split (`identifying`/`commercial` and `identifying`/`budget` respectively). `edgeRoleDecision` refuses any edge write touching a split endpoint with no declared partition outright, falling back to a plain unscoped-Full role check no ordinary role holds — the identical mechanism F208, F235, F254, F265 and F267 have each independently exposed on a different edge. This is that same defect's sixth occurrence, and the second time it has landed on Pitch specifically (`staffed_on`, F265; `logged_against`, F267) without the registry gaining any completeness check that would have caught it on `requires_skill` before a stage ever needed to write it.

**Closed by direct precedent, 25 September 2026.** No founder consultation needed. `governingPartitions: { Pitch: "identifying", Requisition: "identifying" }` declared on `requires_skill` in `packages/schema/src/registry/edges.ts`, matching `staffed_on`'s and `logged_against`'s own `Pitch: "identifying"` precedent: a project's, pitch's or requisition's skill requirement is non-financial descriptive data, never gated behind the commercial or budget partition.

**Status: closed.**
