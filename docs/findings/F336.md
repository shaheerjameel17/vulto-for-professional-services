### F336 — `overtime.approve` takes hours from the caller

**Found while:** briefing Stage 28 (`VRS-F018` part 2), 27 September 2026, by checking the spec's API contract against the code.

The contract `overtime.approve(flagId, loggedHours, expectedHours)` lets the caller supply the hours TOIL is computed from. Accrual is a financial-adjacent entitlement, and a caller-supplied figure is an unverified input; the server already holds the submitted entries and the working calendar. The clearance already exists as `timesheetAnomaly.clear`, whose `ApprovedOvertime` outcome is built (with the re-flagging exemption, `G07`).

**Files:** `docs/Vulto_Specs/VRS-F018_Leave_Policy_Engine.md`, `services/api/src/mutations/timesheet-anomaly.ts`

**Ruling.** **Closed 27 September 2026 by ruling.** There is no `overtime.approve` endpoint. The server derives logged hours, expected hours and the standard day itself, inside `timesheetAnomaly.clear`, which returns `{ toil_days_accrued, capped_at? }`. A read-only `overtime.preview(flag_id)` query returns the same figures before confirmation (the spec's "the manager saw the figure"), from one shared function so preview and clearance cannot diverge. The clearance input gains an optional `acknowledged_toil_days`; a mismatch with the recomputed figure is rejected as `stale-state`.
