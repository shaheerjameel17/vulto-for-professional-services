### F284 — `VRS-F012`'s cost-visibility rule contradicts its own billing-rate decision

Raised 25 September 2026, checking `VRS-F012` directly against the code before writing its Stage 20 brief. The spec's Security Considerations section states: "Cost visibility follows `VRS-F005`'s rule. A viewer without compensation access sees days on bench and not the currency figure" — restated identically in the Interface Specification's System States table ("Restricted | Cost figures follow `VRS-F005`'s rule..."). Both directly contradict the same document's own Decisions Recorded section, two headings above: "Cost figures derive from billing rates, not compensation... This feature never reads a salary," and the preceding Security Considerations bullet itself: "`effective_billing_rate` and `billing_rate_default` are both Tier 0." The already-registered node confirms the Tier 0 reading is the live one — `packages/schema/src/registry/nodes.ts` declares `RevenueGapAlert` with `fixedProtection("Standard", 0)`, a flat single-partition Tier 0 record with no Tier 1/2 split to gate a "viewer without compensation access" against in the first place.

The two bullets read as an artifact of the feature's own pivot away from a compensation-based cost figure (recorded in Decisions Recorded) that was never fully reconciled through the rest of the document: `VRS-F005`'s own cost-visibility gate is real, but it exists because `VRS-F005`'s cost figure (`getBenchForecastCosts`) is compensation-derived, reading the Tier-1/2 `compensation` partition directly. `VRS-F012`'s cost figure deliberately is not — it resolves from `Assignment.effective_billing_rate`, a Tier 0 field, with no compensation read anywhere in its own contract. Two features producing differently-sourced cost figures cannot share one visibility rule between them; copying `VRS-F005`'s rule here re-imports the exact salary dependency this feature was explicitly redesigned to avoid.

**Closed by direct precedent, 25 September 2026.** No founder consultation needed — the document's own later, deliberate correction (Decisions Recorded) controls over the earlier, unreconciled bullet, the same resolution principle F278 already applied to a stale Security Considerations claim in a sibling spec. The stale Security Considerations bullet and the System States table's "Restricted" row are both removed from `docs/Vulto_Specs/VRS-F012_Revenue_Gap_Alert.md`; a caller who can read a `RevenueGapAlert` at all sees every field on it, cost figures included — `RevenueGapAlert`'s own Tier 0, no-partition-split registration already says exactly this, and the spec is corrected to stop contradicting it.

**Status: closed.**
