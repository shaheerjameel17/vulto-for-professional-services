### F236 — VRS-F005's "entirely local" claims include Tier 1/2 data that F199's architecture never caches on device

Raised 23 September 2026 while briefing Stage 13 (`VRS-F005`), reading the spec directly before writing the brief.

**The contradiction.** The spec states three times that the Contextual Intelligence Panel is "entirely local" (the Selecting a row flow, the Panel's own section header, and G04's "resolved entirely from the local store"), immediately followed in each case by a description of the exact same traversal surfacing BurnoutAlert and FlightRiskSignal — both registered `fixedProtection("Manager-restricted"/"Owner and HR Admin only", 2)`, Tier 2. `benchForecast.get`'s API contract claims to resolve "entirely from the local index. No network round-trip," while the same section's Bench computation defines accumulated cost as a function of the employee's compensation, and `Employee` is registered split-protection with its compensation half at Tier 1 (`Finance-restricted`). The feature's Non-Functional Requirements and its offline acceptance criterion both claim full offline functionality "with no read degradation." Per F199's rewritten `VPS-A003`, Tier 0 is the only tier Electric replicates into the device cache; **Tier 1 and Tier 2 are "field-encrypted... fetched on demand... held in memory only"** — never stored on a device, online or off. None of the spec's "entirely local" language is true for BurnoutAlert, FlightRiskSignal, or the bench cost currency figure; all three require a live `protected.read` round-trip under the architecture this feature is about to be built on.

**What is not affected.** The 90-day timeline's bars, dates and bench-day counts genuinely are Tier 0 — `Assignment`, `Project`, `Client`, `GhostResource`, `OpenRole` and `effective_billing_rate` are all registered `fixedProtection("Standard", 0)` — so the timeline's own "no network request" acceptance criterion is correct as written and needs no change. The Contextual Intelligence Panel's `skills`/`openRoles`/`references` fields are Tier 0 too and stay genuinely local.

**Closed by founder-delegated decision, 23 September 2026.** The spec is corrected, not the architecture — the same class of correction F199 itself made to `VRS-F002`/`VPS-F002`, and exactly the "just-in-time, before its own build stage" pattern FDN-104 already established.
1. The Contextual Intelligence Panel resolves its Tier 0 fields (skills, open roles, references) from the device's local Electric-replicated cache, as before. Its Tier 2 fields (BurnoutAlert, FlightRiskSignal) are fetched on demand from the server the instant the Panel opens, gated by `VPS-A004`'s interceptor exactly as `contextualIntelligence.get`'s contract already scopes them, and held in memory only per F199 — never cached. This is one additional network call per Panel open, not zero.
2. Bench cost is split from the rest of `benchForecast.get`. The timeline's bars, dates and bench-day counts stay genuinely local and unchanged. The currency-denominated accumulated cost figure is compensation-derived (Tier 1) and cannot resolve from the device cache; it is fetched by a new, separate, batched on-demand call for the visible cohort — `benchForecast.getCost(employeeIds, window)` — issued after the local render completes and filled in asynchronously, never blocking the 200ms budget. An unauthorized viewer still receives no currency figure, unchanged from the spec's existing rule.
3. The WellnessTriggerEvent exclusion is reworded: not because "an unauthorized device never holds the data to suppress" (a device-sync framing this architecture no longer has), but because `contextualIntelligence.get` never requests that node type at all — Tier 3 stays a deferred end-to-end module per F199, with no read path in this feature regardless of role.
4. The offline claims are scoped to what F199 actually guarantees offline: the timeline, bars, bench regions and day counts (all Tier 0) render fully offline, unchanged. Bench cost figures and the Panel's Tier 2 content require connectivity and show `VPS-D004`'s standard connectivity-required state while offline, exactly as every other Tier 1/2 read in the product now does.

`VRS-F005`'s Depends On line, its Selecting-a-row flow text, its Contextual Intelligence Panel section, its API contracts, G04, its offline acceptance criterion and its "fully functional offline" NFR are all corrected to this reading.

**Status: closed.** Stage 13 is unblocked on this point.
