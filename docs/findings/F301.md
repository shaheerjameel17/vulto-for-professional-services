### F301 — the Stage 23 brief's browser-gate claim was false, and the gate it should have named is real

The Stage 23 brief said, in its Gates paragraph and again in its report checklist, that "whatever device-store browser suite `verify:full` already runs must still pass on this diff", and that no new browser suite was required. The reviewer wrote that sentence without reading `package.json`. Codex traced the brief against the repository's own scripts and CI workflow before writing any product code and stopped, as the stage decision policy requires: the root `verify:full` script is `pnpm verify && pnpm verify:preflight && pnpm --filter @vulto/api test` and runs no Playwright suite at all. The device-store browser suite is a separate command, `pnpm test:sync-browser` (Playwright against real Chromium, real Postgres and real Electric, `packages/graph/sync-browser-tests`, with a `pretest` step that seeds its own environment), and `.github/workflows/slow-lane.yml` runs it as its own `sync-browser` job on every push and pull request, "required for merge". The finding was recorded on the branch (`be925d3`, `fa51a3c`) and `RST-51` moved to Blocked; no product code was written.

**Closed by direct precedent — the brief, not the code, was wrong (F259's own shape), and the slow lane's own required-for-merge status settles what the gate is. No founder consultation needed.** The correction is not merely to the wording, because the gate matters for this change specifically. `cache_search`'s triggers are the first SQL objects beyond tables and indexes that will run inside the real `IDBBatchAtomicVFS` device database; every unit test in `packages/graph` uses the in-memory VFS, and nothing else in the repository exercises the real one. A trigger that is invalid under that VFS, or a cache-version bump that misbehaves against a real existing browser database, would abort `putNode`'s write and surface only there. Separately, the `dump` operation the suite's A003-T56 scan uses (`packages/graph/src/sync-client/host.ts`) reads every table in `sqlite_master`, so the "no Tier 1 or Tier 2 value reaches any browser storage" test will scan `cache_search`'s contents automatically — a free, real check that the index holds only Tier 0 text.

The ruling, in full. (1) `pnpm test:sync-browser` — the full suite, not only the A003-T56 `--grep` — is an additional required gate for Stage 23, run after `pnpm stack:up` (Electric is already in `docker-compose.yml`) and `pnpm --filter @vulto/api db:migrate`, with the environment the slow-lane job uses (`SYNC_BROWSER_DATABASE_URL`, `ELECTRIC_URL=http://localhost:5133`, `ELECTRIC_SECRET`); the report states the exact command and its result. (2) If the builder's environment genuinely cannot run it (no Chromium or no Electric), the report says so plainly and records the pushed branch's slow-lane `sync-browser` job conclusion with its run URL instead — the workflow needs no extra setup on push — but a silently skipped gate is not acceptable. The reviewer's own shell has no Docker and no GitHub credentials, so either form is disclosed reliance on the builder's terminal output or CI record, the same class of accepted limitation as the Postgres-backed suite. (3) One added assertion in the existing `packages/graph/sync-browser-tests/sync.spec.ts`, not a new suite and not outside `packages/graph`: after the suite's existing seeding and sync of entities, `dump()["cache_search"]` holds exactly one row per non-soft-deleted `cache_nodes` row whose `node_type` is in `SEARCHABLE_NODE_TYPES`, and one seeded Employee's `search_text` contains its lowercased `full_name`; where the suite already deletes or moves a row out, assert the row's removal from `cache_search` the same way, but build no new scenario for it. (4) The brief's Gates paragraph, a new Do item 8, a new Done criterion and the report checklist are corrected accordingly, and `docs/Reviewer_Handoff.md` section 24 is corrected to match.

**Status: closed.**
