### F319 — the server refuses generic Notification writes with role before the feature guard runs

**Found while:** Codex tracing the F317 and F318 test assertions before writing product code, 26 September 2026 (stage report `33804c3`); ruled by the reviewer the same day.

F317 and F318 required a server refusal of exactly `requires-feature-mutation` for a generic `Notification` create and for the three generic `delivered_to` edge mutations. The pipeline calls `authorizeWrite` for every plan check and returns its denial before `plan.validate` runs (`pipeline.ts:275–298`), and the generic feature guards live in `validate` (`mutations/foundation.ts:120`, `:161`, `:210`, `:242`, `:274`, `:314`, `:349`). A create for a not-yet-existing Notification fails the `recipient` scope closed (no stored row or edge), so authorization returns `role` first; and `foundation.ts::edgeTarget` returns the endpoint node types but omits `fromNodeId` and `toNodeId`, so `interceptor.ts::edgeRoleDecision` builds no row context and the scoped `full` on Notification resolves to none, again `role` before the guard. The same trace corrects F317's premise: the predicted Owner or HR Admin re-addressing path was already denied in practice, because the actual caller omits the ids; the reservation is defense in depth against `edgeTarget` gaining ids later.

**Files:** `services/api/src/mutations/pipeline.ts`, `services/api/src/mutations/foundation.ts`, `services/api/src/permission/interceptor.ts`

**Ruling.** **Closed 26 September 2026 by ruling.** No change to authorization order (the ordering is a deliberate property: nothing is validated for a caller who may not write) and none to `edgeTarget`. The guards stay as ruled. Server tests assert what each path really does: `role` or `requires-feature-mutation` for the create and the three edge mutations (nothing written, observed reason recorded), and exactly `requires-feature-mutation` for a recipient's generic `updateNodeFields`, `softDeleteNode` or `transitionLifecycle` on an existing Notification, the one generic path where authorization passes and the guard is all that stands; client tests assert exactly `requires-feature-mutation`. Lesson: when a brief asserts a specific refusal reason, trace which gate refuses first.
