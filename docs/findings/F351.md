### F351 — the Employee profile is a real Tier 0/Tier 1 hybrid, not one query

**Found while:** briefing UI-2, 27 September 2026.

`VRS-F002` requires the profile's Tier 0 fields (name, job title, contact, dates, `billing_rate_default`, notes, and the rest of `operationalShape`) to render offline from the cache, and requires compensation to be "fetched, never cached... every read is an audited `protected.read`," with structural absence — not a disabled section — for a viewer without the grant. One screen therefore has two data sources with two different failure modes, exactly the pattern F341 already established for the palette's skill-match group: a local device-query for Tier 0, and a live authorized server call for Tier 1, never merged into one client-side object that could be cached whole.

**Files:** `apps/roster-web/src/app/(shell)/people/[id]/page.tsx`, `apps/roster-web/src/lib/profile.ts`, `services/api/src/permission/employee-queries.ts` (`getEmployee`), `apps/roster-web/src/lib/skill-matches.ts` (the existing typed-`fetch` pattern F341 built)

**Ruling.** **Closed 27 September 2026 by ruling.** Tier 0 fields come from the same local `employee.get`-style `device-query` the directory uses (F350), keyed by id, and render at once from the cache, offline included. Compensation comes from a small typed `fetch` to the existing `getEmployee` router entry (which already combines the Tier 0 read with an audited Tier 1 compensation read), reusing `skill-matches.ts`'s `fetch`/`apiOrigin`/`credentials: "include"` pattern rather than inventing a second one; it is called only when the signed-in viewer's real role can hold the grant, held in memory for the session, never written to `localNodes`, and a `null`/absent response renders the Compensation section as structurally absent — the exact conditional-spread pattern `lib/profile.ts`'s `buildEmployeeProfile` already implements, kept and re-pointed at the real fetch instead of the fixture flag. A failure or unauthorized answer degrades that one section to `requires-connection`, mirroring F341's skill-match group; nothing else on the page is affected.
