### F234 — reduced-hours periods are required for reads but have no named write path

Raised 22 September 2026 while tracing Stage 12's required UAE Ramadan acceptance test into the corrected mutation surface. `VRS-F004` defines `reduced_hours_periods` as an inline JSON array on WorkingCalendar, makes its factor the final step of the working-day resolution order, describes add/edit/remove UI, and requires a UAE Ramadan period at factor `0.75` to return six hours. It also says provisional periods have a confirmation mechanism. Yet the only WorkingCalendar write is the exact corrected signature `calendar.update(calendarId, workingWeek, dailyHours, expectedVersion)`, which accepts no reduced-hours periods. No other named mutation creates, edits, removes or confirms an inline period. Initial jurisdiction templates specify only weekdays and standard daily hours.

Under `VPS-A003`, the graph can be written only through a named mutation. An integration test could bypass that rule by inserting a crafted node directly, but the product could never create the state the test pretends to exercise, and the required optimistic handler would still have no contract to mirror.

**Ruling — closed 22 September 2026.** `reduced_hours_periods` is edited exclusively through `calendar.update`, never through a mutation of its own — exactly consistent with its own schema note that it is held "on WorkingCalendar rather than as its own node, since it has no independent lifecycle," and with F225's own already-recorded phrase that its confirmation record is "the superseding WorkingCalendar version's own stamp," which only makes sense if confirming one supersedes the calendar. `calendar.update` gains one more optional parameter: `reducedHoursPeriods?`. Omitted, the new version carries the prior version's array forward unchanged — the same copy-forward convention F230 gave Holiday. Provided, it replaces the array wholesale on the new version: adding a period, editing one, removing one and confirming a provisional one (rewriting its `is_provisional`/dates) are all simply a new array passed to the same call, with no separate write path, no new node type and no dedicated confirmation mutation. The optimistic `calendar.update` handler (F233's sibling work, same Do item) carries `reducedHoursPeriods` through the identical copy-forward-or-replace logic.

**Status: closed.** Stage 12 is unblocked; F227 through F234 together give it everything G01–G08 need to be built and tested.
