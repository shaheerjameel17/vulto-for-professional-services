### F352 — `lib/viewer.ts`'s role toggle is shared by three screens; UI-2 owns only its Profile use

**Found while:** briefing UI-2, 27 September 2026.

`apps/roster-web/src/lib/viewer.ts` (`ViewerRole`, `cohortFor`, `cohortIdsFor`, `canSeeCompensation`, `viewerEmployee`) is imported by the Employee profile's `ProfileViewer` `ToggleGroup`, and — its own comment says so — by Home and by the Bench Forecast fixture screens as well, neither of which UI-2 touches (they are UI-3 and a later stage). Replacing the file or its exported shape to suit the profile screen alone would silently break the other two, which still read fixture data and have not been briefed yet.

**Files:** `apps/roster-web/src/lib/viewer.ts`, `apps/roster-web/src/app/(shell)/people/[id]/page.tsx`, the Home screen, the Bench Forecast screen

**Ruling.** **Closed 27 September 2026 by ruling.** UI-2 removes the `ToggleGroup`/`ProfileViewer` fixture switch from the profile page only, replacing its one call site with the real signed-in principal's role (already available from the shell's auth/session context the bootstrap already carries). `viewer.ts`'s exported functions, types and signatures are left exactly as they are — Home and Bench Forecast keep calling them against fixture data until their own stages land. If `canSeeCompensation`'s signature needs a real role value rather than the fixture's `ViewerRole` shape, the two are kept compatible (the real role mapped onto the same union) rather than the shared file forked or duplicated.
