### F278 — `UtilizationSnapshot`'s policy row cannot be a literal reuse of either existing Employee row

Raised 25 September 2026 by the reviewer, checking `VRS-F011` directly against `packages/schema/src/policy/policy-table.ts` before writing its Stage 19 brief. `VRS-F011`'s Security Considerations section states `UtilizationSnapshot` "follows Employee's Standard, Tier 0 visibility: Owner and HR Admin full, Manager scoped to direct reports, Team Member their own. A deliberate reuse of an existing rule, not a new category" — restated identically in the System States table ("A Team Member sees their own pulse bar and the agency aggregate... A Manager sees their reports"). But `Employee` registers two Tier 0 policy rows, `Employee:operational` and `Employee:compensation`, and neither matches this description as a whole. `Employee:operational`'s `team-member` cell is `Read (own + team)` — reusing this row wholesale would let any Team Member see a colleague's individual utilization figure on that colleague's own profile, contradicting the spec's explicit "their own" restriction. `Employee:compensation`'s `manager` cell is `Restricted — "Visible to Finance Admin"` — reusing this row wholesale would hide a Manager's own direct reports' utilization from them entirely, contradicting the spec's explicit "Manager scoped to direct reports."

**Closed by direct precedent, 25 September 2026.** No founder consultation needed — composing a new policy row from the matching cells of two existing rows, rather than copying either wholesale, is the same shape of reasoning already applied when `logged_against` gained `readSufficientEndpoints: { Assignment: true }` on `assigned_to`'s own precedent (F262/F275) while still needing a second, genuinely new mechanism for its other endpoint. `UtilizationSnapshot`'s own row: Owner and HR Admin `FULL_ANY()` (both existing rows agree); Manager `cell("full", "direct-reports", "Full (direct reports)")`, `Employee:operational`'s own cell — the shape the spec actually describes; Team Member `cell("read", "own", "Read (own only)")`, `Employee:compensation`'s own cell — the closer analog for an individually-sensitive per-person figure than general profile data; Finance Admin `READ_ANY()`, `Employee:operational`'s own Tier 0 default for a role the spec does not otherwise restrict. `docs/Vulto_Specs/VRS-F011_Billable_vs_Non-Billable_Pulse.md`'s Security Considerations section is corrected to state this composed row explicitly rather than the ambiguous "reuse" language that produced this finding.

**Status: closed.**
