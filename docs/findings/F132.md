### F132 — no edge type except `managed_by` has a defined CRDT storage representation

Surfaced alongside F131, same review. `packages/graph/src/worker/document-node-fragments.ts` defines the complete storage contract for node fragments — a reserved `LoroMap` container, a frozen key scheme. Searched for the equivalent for a generic edge and found none: the only edge-shaped Loro representation anywhere in the codebase is `managed-by-materialization.ts`'s Movable Tree, and `managed_by` is not stored as a generic edge at all — per F104, it is derived, one-way, from Tree state, specifically so it never needs one. `VPS-A002` registers roughly ninety other edge types (`has_skill`, `assigned_to`, `contracted_with`, and the rest) with endpoints and, for a few, lifecycle policy — but none of them has a container name, a key format, or any committable representation to write to.

This blocks more than FDN-53: every future feature that creates any edge other than `managed_by` hits the same wall. Designing the convention — container naming, key scheme, whether it needs per-edge-type conflict semantics analogous to `managed_by`'s causal ordering — is an architectural decision on the order of `VPS-A001`/`VPS-A002`, not something to improvise inside a stage scoped for mutation *interception*.

**Open, raised not decided.** FDN-53 stage 2 scopes edge writes to authorization-check-only: permit/deny is computed and exhaustively tested against the existing policy table and graph traversal rules, but nothing commits. The storage convention itself is logged here for a dedicated design pass, not decided as a side effect of this stage.

**Closed by FDN-92.** The dedicated design pass this finding asked for: a Q1–Q6 decision memo, three staged checkpoints, and a real-stack proof. The convention:

- **Storage.** A reserved root `LoroMap` named `__vulto_edge_fragments`, sibling to `__vulto_node_fragments`; the key is the edge's own `edge_id` verbatim; each edge is its own nested `LoroMap`. The container name and key scheme are frozen on-disk contract. The registry triple `(edge_type, from_node_type, to_node_type)` is recovered per instance at materialization, not stored in the key — a composite key would collapse `governed_by`'s four registrations, or PayRun's two concurrent `governed_by` edges, or two same-endpoint edges with different ids and intervals.
- **Conflict semantics.** Last-write-wins per field, via the nested per-edge `LoroMap` — identical to node fragments. One exception among stored edges: `scoped_to_entity` (single-active-outgoing, not Tree-backed), where the writer must close the prior edge and open the new one in the same batch; `validateSingleActiveOutgoing` and the SQLite `graph_edges_one_open_outgoing` unique index are the backstops. `managed_by` stays Tree-derived and untouched.
- **Commit path.** `mutate` / `authorizeMutationBatch` extended: a batch that changes only `__vulto_edge_fragments` is diffed and each changed edge gated by `authorizeEdgeWrite` before commit, rather than refused as `unsupported`.
- **Authorization.** `authorizeEdgeWrite` (F136) now resolves a split endpoint's governing partition from a static, reviewed `governingPartitions` field on the FDN-45 / FDN-75 edge-type registry — never a value the write delta supplies. A split endpoint with no entry stays at the conservative `none`. Six entries at close: `has_skill` / `holds_certification` / `assignment_of` → `{ Employee: operational }`; `membership_in` → `{ Workspace: display }`; `assigned_to` / `membership_of` → none.
- **Intervals.** Caller-supplied verbatim; the storage layer derives nothing, and never defaults `effective_from` to a wall-clock now (the F124 mistake).

Recorded in `VPS-A002`'s Universal edge conventions section, alongside the F104/F124 `managed_by` material. Proven on the real stack (real Chromium, real Postgres, real FDN-84 sealed store, real Loro + SQLite WASM) by six FDN-92 Stage 3 tests — two-device union, field-by-field merge on one `edge_id`, close/reopen/re-materialize, `governed_by` disambiguation, split-endpoint denial, and offline convergence — plus both mutation spot-checks (a no-op commit that skips materialization fails the round-trip; a key scheme that collapses `(edge_type, from_node_id)` fails the disambiguation).

FDN-92 delivers the storage and commit mechanism for all ~90 generic edge types. Authorization is real for any edge type whose split endpoints, if any, have a `governingPartitions` entry. RST-33 and FDN-85 still need their own memos to build the `has_skill` / `holds_certification` / `membership_in` features — FDN-92 removed the wall F132 named, it did not build those features.
