### F207 — `Client`'s write authority disagrees between `VPS-A002` and `VPS-F008`

Raised 21 September 2026, building Stage 3's write-authority gate.

**The disagreement.** `VPS-A002`'s Cross-Suite Node Ownership table (and its `OWNERSHIP_REGISTRY` in `packages/schema`) makes Vulto Sales the permanent owner of `Client` and Projects the bootstrap writer "until Sales activates; Sales thereafter". `VPS-F008`'s write-authority policy lists `Client` as "Not applicable. Roster was never authorized to write it, so there is no authority to hand off", and its `ApplicationActivation` enumerates only the four applications that own a node type Roster bootstraps, deliberately excluding Sales.

**The reading applied.** `VPS-F008` governs: `Client` is not applicable, so the gate applies no restriction to it. The gate treats an owner outside the four activatable applications as having nothing to hand off to. This is recorded as a finding rather than left as a micro-decision, because it is a real disagreement between two documents. `VPS-A002`'s ownership row and the registry entry need reconciling in the FDN-104 specification sweep.
