### F311 — muting has no valid target and no home

**Found while:** briefing Stage 25 (`VPS-F003`), 26 September 2026, by checking the spec against the code before writing the brief.

Muting (S04) has no valid target and no home. The spec holds `muted_source_types` on WorkspaceMembership, but a `WorkspaceMembership` node is written only by the membership projection and carries exactly `VPS-F001`'s fields (`services/api/src/graph/membership-changes.ts`, `founding.ts`), and G05 permits muting only `Informational` sources while every rule that can ship now is `ActionNeeded` (a manager's revenue gap and anomaly flag, an employee's timesheet reminder).

**Files:** `services/api/src/graph/membership-changes.ts`, `services/api/src/graph/founding.ts`, `docs/Vulto_Specs/VPS-F003_Notification_and_Alert_Center.md`

**Ruling.** **Closed 26 September 2026 by ruling.** `notification.mute` and the preference field are not built; the registry records each rule's `category`, and a conformance test asserts that no registered rule that produces `ActionNeeded` could ever be mutable, so G05 holds by construction. The stage that registers the first `Informational` rule decides where the preference lives (a field on WorkspaceMembership needs a change to the projection's contract, a separate recipient-only node type needs a registry entry); it is not decided here because nothing exists yet to mute.
