### F213 — `member.projection_state` is vestigial

**Found while:** Stage 7, making workspace creation, removal and role change single server transactions.

The column and its check constraint (`pending`, `confirmed`, `revocation-pending`) carried the state of a two-phase protocol in which a device confirmed each membership change in its local graph. That protocol is gone. A new membership is `pending` only for the instant between the two steps of creation, removal now ends in `revoked/confirmed`, and `revocation-pending` is never written. Authorization queries still filter on `confirmed`, so the column is harmless, but it names a state machine that no longer exists.

**Closed by founder-delegated decision, 22 September 2026:** the column and its check constraint stay; the column is dead in practice, not in the schema. Revisit during the FDN-104 spec sweep, not before. (Removing it means changing Better Auth's `member` additional fields and every query that reads it (the session guard, the principal resolver, the audience materializer, the shape proxy). That is a schema change to the authentication model and is left for that sweep.)
