### F248 — VRS-F007's Depends-On section omits its real forward dependency on VRS-F028's unbuilt OpenRole

Raised 23 September 2026 while checking `VRS-F007` directly against the code before writing the Stage 15 brief.

**The gap.** `VRS-F007`'s Depends-On line names `VRS-F002`, `VRS-F005`, `VPS-A002`, `VPS-A003` and `VPS-A004` but not `VRS-F028`. Its own text nonetheless gives Ghost creation "an optional link to an existing OpenRole," its API contracts include `ghostResource.linkOpenRole(ghostId, openRoleId)`, and the registered `placeholder_for` edge (GhostResource to OpenRole, confirmed in `packages/schema/src/registry/edges.ts`) exists specifically to carry that link. `OpenRole` itself is already a registered node type (`packages/schema/src/registry/nodes.ts`, owner `VRS-F028`, Tier 0) but has no field schema, no mutation and no create path anywhere in the repository — confirmed by a repository-wide search. `VRS-001`'s Feature Register places `VRS-F028` (F17) well after `VRS-F007` (F04) in MVP order, so no `OpenRole` node can exist by the time Stage 15 ships. This is structurally the same shape as F239: a spec's dependency list reads as complete and unconditional while a real, later-feature-owned prerequisite goes unnamed.

**Closed by founder-delegated decision, 23 September 2026.** Same treatment as F239, extended rather than reinvented. `ghostResource.create` accepts the optional `openRoleId` and `ghostResource.linkOpenRole` writes the `placeholder_for` edge now — the mechanism is trivial (an edge write against an already-registered pair) and there is no reason to gate it behind `VRS-F028` landing first. What changes is documentation only: `VRS-F007`'s Depends-On section gains a Partial forward dependencies line — "`VRS-F028` supplies OpenRole creation; until it exists, `openRoleId` has no real targets to link, and every Ghost is created without one" — mirroring `VRS-F005`'s own line for `VRS-F006`/`VRS-F007`/`VRS-F009`/`VRS-F010` exactly. Nothing about Stage 15's build changes; this closes a documentation gap, not a code gap.

**Status: closed.**
