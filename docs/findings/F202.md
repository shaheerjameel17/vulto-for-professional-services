### F202 — the sync audience, and three facts closed before implementation

Closed 21 September 2026, before implementation began, so the implementing agent has nothing to decide.

**The sync audience.** Electric serves single-table shapes with a where clause, and supports subqueries whose dependencies it tracks. Generating a different shape per role and scope would have meant re-expressing `own`, direct-report and subject-exclusion scope as SQL where clauses — a second implementation of the permission rules. Instead the interceptor writes an explicit audience of identifiers (`sync_node_audience`, `sync_edge_audience`), maintained in the transaction of every mutation and recomputed per workspace on any membership, role or `managed_by` change; every device subscribes to the same two shapes filtered by it, through an authenticated API proxy that sets every shape parameter server-side. The publication allowlist gains the two audience tables, which carry identifiers only. `VPS-A003` A003-T57, A003-T58 and new A003-T72; `VPS-A007` gate 6 and A007-T03.

**Local key provider.** Development and CI cannot call AWS KMS. A `LocalKeyProvider` behind the same `KeyProvider` interface takes its root key from the environment; production refuses to start with it. A003-T73.

**Browser storage and tabs.** OPFS synchronous access is unavailable in a SharedWorker, and one cache shared by every tab is required (A003-T66). The web cache therefore uses `wa-sqlite`'s `IDBBatchAtomicVFS` inside a SharedWorker, falling back to a dedicated Worker holding a `navigator.locks` lease where SharedWorker is unavailable. `VPS-A001`.
