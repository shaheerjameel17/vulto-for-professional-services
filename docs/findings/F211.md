### F211 — Electric signals audience removals as `move-out` events, and the client protocol has more parameters than the proxy list named

**Found while:** Stage 6, running the sync browser suite against real Electric 1.8.1 and `@electric-sql/client` 1.5.28.

**Move-out.** `VPS-A003` "Reads" says a person's cache is kept equal to their audience, and the brief's replication item says to apply inserts, updates and deletes. For a shape filtered by a subquery (`node_id IN (SELECT … FROM sync_node_audience …)`), removing a row from the audience does not delete the row in Postgres, so Electric cannot send a `delete`. It sends `{"headers":{"event":"move-out","patterns":[{"pos":1,"value":"<hash>"}]}}`, and each row it delivered carried `headers.tags: ["<pos>/<hash>"]`. The client must remember each row's tags, remove the tags a move-out names, and delete any row left with none. A row moving back in arrives as an ordinary insert.

**Implemented:** `cache_tags (template, row_id, tag)` in the device cache (identifiers only), tag bookkeeping on every change, and move-out handling in `SqliteCache.applyBatch`, in the same transaction as the cursor. Tested by `engine.test.ts::a move-out removes rows whose only tag left, and keeps rows another tag still admits` and by the browser test `removing the member's role removes the rows they may no longer read from the cache`, which fails without it. The tag format `<pos>/<hash>` is observed behavior of the pinned version, not a documented contract: the client library types call a tag an opaque string. Upgrading Electric or the client re-runs both tests, which is the guard.

**Proxy parameters.** The pinned client also sends `expired_handle` and `cache-buster` (cache-busting after a stale handle) and `log=full` (its default). The proxy forwards those and nothing else beyond `offset`, `handle`, `live` and `cursor`; `log` is accepted only as `full`, because `changes_only` would narrow what the shape returns. Everything else, including `table`, `where`, `columns`, `params`, `replica`, `subset__*` and `secret`, is still a `400`.

**Specification correction (applied, 21 September 2026, delegated at the Stage 6 review):** `VPS-A003` T72 lists the forwarded parameters as `offset`, `handle`, `live`, `cursor`; it should add `expired_handle`, `cache-buster` and `log=full`. `VPS-A003` "Reads" should say that a subquery-filtered shape reports audience removals as `move-out` events over row tags, and that the device cache tracks tags to apply them.
