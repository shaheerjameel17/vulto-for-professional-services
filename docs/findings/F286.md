### F286 — `VRS-F013`'s spec still describes the dropped local-first architecture

Raised 25 September 2026, checking `VRS-F013` directly against the code before writing its Stage 21 brief. This document was decided at founder level on 31 July 2026 and never revisited since. Its Interface Specification says persistent match results resolve "Entirely local. Within 200ms for 150 employees and 50 projects"; the ad-hoc mode is specified "Within 10ms of the third character typed," a per-keystroke budget only a local index scan could meet; the System States table's Syncing row reads "Skeleton rows within each requirement Section" with no mention that a request ever leaves the device; the Feature Acceptance Criteria include an explicit "GIVEN the device is offline... THEN both render fully from the local graph with no network attempt and no degradation"; and the Non-Functional Requirements list "Full functionality offline in both modes." None of this matches the server-authoritative architecture every built feature now runs on, and — because this feature owns Skill's schema and blocks three others — leaving it uncorrected would have briefed Stage 21 against an architecture that no longer exists.

**Closed by direct precedent, 25 September 2026.** No founder consultation needed — the identical class of correction F236, F244 and F282 already made for three sibling specs. `docs/Vulto_Specs/VRS-F013_Skill-to-Project_Matcher.md` corrected throughout: both `project.getMatchResults` and `skillMatcher.adHocSearch` become ordinary server-side authorized queries per `VPS-A004`'s interceptor, budgeted at 300ms rather than a per-keystroke local scan; a new Technical Architecture subsection states plainly that SkillGap detection and auto-resolution run as a reactive `afterCommit` write on `has_skill`, exactly like `timesheetAnomaly.evaluate` (Stage 18) and `revenueGapAlert.evaluate` (Stage 20); the System States table's Syncing row, the offline acceptance criterion and the offline NFR are all removed; the ad-hoc mode is noted as exercised directly this stage, since `VPS-F002`'s palette that will eventually call it does not exist yet — the same deferral pattern `VRS-F012`'s Inbox surface followed at Stage 20.

**Status: closed.**
