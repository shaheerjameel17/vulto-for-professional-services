### F239 — the Stage 13 local Bench Forecast query cannot implement its required Pitch-day exclusion

Raised 23 September 2026 while tracing Stage 13 (`VRS-F005`) from its corrected brief into the device-cache query layer, before implementation.

**The conflict.** `VRS-F005` defines bench time as working days with no Active Assignment coverage **less every day carrying Pitch-categorized time**. G02 repeats that rule, and an acceptance criterion requires six Pitch days to disappear from the bench region and its cost. The same spec says the Pitch exclusion moved into this feature so it would be implemented once rather than supplied by `VRS-F012` later.

Stage 13 Do item 3 defines the local query over `Assignment`, `Project`, `Client`, `GhostResource`, `OpenRole`, `Entity`, `WorkingCalendar`, `Holiday` and `WorkingPattern`. It does not include `TimesheetEntry`, the only record that can say a person logged Pitch time. Checked directly against the registry: `TimesheetEntry` (owner `VRS-F010`), `Pitch` (owner `VRS-F009`) and the `logged_against` edge connecting them (owner `VRS-F010`) are all structurally registered, but `packages/schema` has no field schema beyond the registry entry, no named mutation, and no typed local query contract for any of the three — a repository-wide search for a mutation touching either node type found none. `VRS-001`'s Feature Register confirms `VRS-F009` (F18) and `VRS-F010` (F08) both sit strictly after `VRS-F005` (F03) in MVP order.

**Why this is the same class of gap as F236, not a new one.** `VRS-F005`'s own Depends-On section already distinguishes hard dependencies from partial forward dependencies, and already names exactly this pattern twice: `VRS-F006` supplies rate resolution ("until it exists, `effective_billing_rate` is written as `billing_rate_default`") and `VRS-F007` supplies Ghost rows ("until it exists, none are rendered"). Both are explicit, both degrade gracefully, and neither blocks this feature. `VRS-F009`/`VRS-F010`'s Pitch-time dependency is structurally identical — G02's own prose simply never received the same treatment, so it reads as an unconditional requirement Stage 13 cannot meet.

**Closed by founder-delegated decision, 23 September 2026.** `VRS-F005`'s Partial forward dependencies line is extended to name `VRS-F009` and `VRS-F010`: until both exist, the Pitch exclusion is not applied, and bench periods compute from Assignment coverage alone. This degrades toward false amber — a person pursuing new business reads as bench-idle until the taxonomy exists to say otherwise — and never toward hiding a real gap or fabricating data, the same safe-direction reasoning F226 applied to deferring the working-day index and F236 applied to deferring Tier 2 Panel content. G02's table row, the bench computation formula's prose, the Pitch acceptance criterion, the Out of Scope list and the Decisions Recorded note are all corrected to record the deferral rather than describe unconditional behavior Stage 13 cannot build. Stage 13's Do item 3 query contract needs no correction — it was already right to omit `TimesheetEntry`; the spec was wrong to imply otherwise.

**Status: closed.** Stage 13 is unblocked; it builds no `TimesheetEntry`, `Pitch` or `logged_against` write or read path, and the Pitch-day exclusion becomes a named follow-up for whichever stage builds `VRS-F009`/`VRS-F010`.
