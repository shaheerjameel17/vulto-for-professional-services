### F364 — the slow lane's UI-1 palette timing gate is a pre-existing flake, not a UI-2 regression

**Found while:** Independently verifying Codex's UI-2 merge report. Codex merged UI-2 to `main` as `c1716fd` with reviewer notes at `85919f3`, and reported `slow-lane` failing twice at that head: `packages/graph/sync-browser-tests/inbox-palette.spec.ts:456`, `expect(timings.queryP95).toBeLessThan(30)`, measuring 35ms then 31.2ms/32ms on rerun. That assertion belongs to UI-1 (`FDN-131`), not UI-2, and UI-2 touched no code on its path. Checking the UI-2 stage report's own CI history for the identical assertion found it already flaking during branch development, on a run that touched none of UI-1's code either: [slow-lane 36314136759](https://github.com/shaheerjameel17/vulto-for-professional-services/actions/runs/36314136759) failed the same line at 38.9ms while 31 of 32 other tests passed, including both new UI-2 themes; the very next push, with no code change to the failing path, ran the identical suite green ([slow-lane 36314952430](https://github.com/shaheerjameel17/vulto-for-professional-services/actions/runs/36314952430)). Reading `main`'s own public Actions history independently (this shell has read-only API access, no push credentials) confirms the same shape at the merge head: `85919f3` failed `slow-lane`, `eb98cec` was cancelled (superseded a minute later), and the last clean `slow-lane` run on `main` before the merge, `2648caf` (27 September), was green — consistent with a marginal, environment-sensitive timing budget rather than a UI-2-introduced cost. The assertion itself (`packages/graph/sync-browser-tests/inbox-palette.spec.ts:456`) is a real-browser CI-runner wall-clock measurement with a fixed 30ms ceiling and no tolerance for runner variance, the same shape F305 already found and repaired once for a different suite/assertion.

**Files:** `packages/graph/sync-browser-tests/inbox-palette.spec.ts` (the `queryP95 < 30` assertion at line 456); CI history on `main` and on `codex/ui-2-people-profile` (public Actions API, read-only).

**Ruling.** **Raised by the reviewer, 28 September 2026. Repair deferred to its own remediation; left open, following F305's own precedent** ("the repair is not this stage's job... becomes a baseline comparison... open finding, not closed"). RST-56 is not blocked by this: the founder's visual acceptance gate is unaffected, `fast-lane` is green, and the failure is on unchanged UI-1 code with a documented pre-merge flake history. Codex is instructed not to touch the threshold, the test, or any UI-1 code to chase this without a ruling. The repair, when scheduled, should either raise the ceiling to absorb measured CI-runner variance (the observed range so far is roughly 31–39ms against a 30ms budget) or convert the assertion to a multi-sample/retry-tolerant check, whichever the next reviewer finds true to what F340's original NFR actually needed; a single generous constant is not assumed correct in advance. Tracked in Notion (Vulto Issues (Engineering)) alongside this finding.
