### F288 — a Manager cannot attach a Project skill requirement under the current edge policy

Raised 25 September 2026. Codex began implementing Stage 21's `project.attachSkillRequirement` mutation and, per standing build practice, traced its own Manager-caller assumption into the policy table before writing product code. `packages/schema/src/policy/policy-table.ts`'s `MATRIX_OVERRIDES.Project` grants Manager `READ_ANY()` on Project, not Full — confirmed by direct read. `requires_skill`'s registration in `packages/schema/src/registry/edges.ts` declared no `readSufficientEndpoints`, so `edgeRoleDecision`'s default applied: a caller must hold unscoped Full on both endpoints to write the edge. A Manager attaching a skill requirement to a Project they can see, but do not own outright, was therefore denied — exactly the outcome Stage 21's own brief did not intend.

This is F262's own shape recurring on a second edge. F262 (Stage 16) resolved the identical condition for `assigned_to`/Project — Manager holding `READ_ANY()`, not Full, on the Project endpoint of a structural edge — by declaring `readSufficientEndpoints: { Project: true }` on `assigned_to`'s registration, "mirroring `VPS-A004`'s own read-traversal rule": a caller who can already read the node does not need general write authority over it just to attach a relationship edge to it. `requires_skill` and `assigned_to` are both edges from a dependent node (SkillGap / Assignment) onto Project, both intended to be writable by a Manager who can merely read the Project in question, and both denied by the same unscoped-Full default before their fix. No genuine architectural fork exists here; the fix is the direct, structurally identical application of an already-decided rule.

**Closed by direct precedent, 25 September 2026.** No founder consultation needed. `readSufficientEndpoints: { Project: true }` added to `requires_skill`'s registration in `packages/schema/src/registry/edges.ts`, alongside a comment citing F262 and F288. No policy-table change, no spec-text change: `MATRIX_OVERRIDES.Project`'s Manager `READ_ANY()` row is correct as built, and `docs/Vulto_Specs/VRS-F013_Skill-to-Project_Matcher.md` already assumes only that a Manager can attach a skill requirement, not by what mechanism — F262 itself required no spec correction for the same reason.

**Status: closed.**
