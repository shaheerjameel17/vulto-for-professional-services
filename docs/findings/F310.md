### F310 — email, push and the Inbox surface are not buildable now

**Found while:** briefing Stage 25 (`VPS-F003`), 26 September 2026, by checking the spec against the code before writing the brief.

The spec's surfaces and channels are not all buildable now: the email channel (S05) needs `EmailService` from `VPS-A006`, which does not exist; push is `VPS-F011`; the Inbox content, unread indicator, keyboard map and inline actions are UI (`VPS-D004`'s Inbox shell), and `apps/roster-web/src/app/(shell)/inbox/page.tsx` is still the prototype placeholder (its sidebar count is a hard-coded 7 in `nav.ts`).

**Files:** `apps/roster-web/src/app/(shell)/inbox/page.tsx`, `apps/roster-web/src/nav.ts`, `docs/Vulto_Specs/VPS-F003_Notification_and_Alert_Center.md`

**Ruling.** **Closed 26 September 2026 by ruling, on the deferral every prior stage has made.** This stage builds the data layer only: the Notification node and its access, the rule registry and engine, the read-state mutations, and the device queries that return the Inbox's three groups and the unread count. No email, no push, nothing under `apps/`. `category` is set on every notification so a later stage delivers email for `ActionNeeded` without touching the producers; G08 is satisfied by construction because no other channel exists.
