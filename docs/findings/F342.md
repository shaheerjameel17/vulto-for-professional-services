### F342 — "actionable in place" cannot be fully built: only read-state actions exist

**Found while:** briefing UI-1, 27 September 2026.

The specs say every Inbox item is actionable in place (approve leave, clear a flag). Only three notification mutations exist (`notification.markRead`, `dismiss`, `markAllRead`); the source features' actions (`VRS-F019` leave approval and the rest) are unbuilt, and a `Notification` carries only a message, a category, a source node type and id and a rule id, no title and no link.

**Files:** `docs/Vulto_Specs/VPS-F003_Notification_and_Alert_Center.md`, `packages/schema/src/notification.ts`

**Ruling.** **Closed 27 September 2026 by ruling.** This stage builds the in-place actions that exist: **Mark read**, **Dismiss** and **Mark all read**, plus an **Open** action where the source resolves to a route that exists (an `Employee` source opens that person's profile, `/people/<id>`; any other source type shows no Open action until its screen exists). No fabricated approve or clear buttons, no client-side fake actions. The row's icon comes from `source_node_type`, its body is `message`, its time is `created_at`. Source-specific in-place actions arrive with each source feature's own stage.
