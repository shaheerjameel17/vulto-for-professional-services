### F199 — the local-first, device-canonical architecture is reversed

**Founder decision, 20 September 2026.** After the six-week foundation build, a review weighed what the architecture would cost every feature built on it. Findings that decided it:

- **Feature cost.** 46 of 78 feature specifications depend on Tier 1 or Tier 3 behavior or on work running "on an authorized device". Stateful workflows needed bespoke conflict designs under offline CRDT merge. Estimated effect: roughly double the effort per feature, more for the financial features.
- **Server capability.** Margin alerts, scheduled payroll reports, exports, integrations, the Sync API and the intelligence engine could run only while an authorized person's device was online, because the server could not read rate cards or pay data.
- **Business continuity.** Tier 1 key loss without two of three recovery holders would permanently lose payroll history, and support could not help. In a small agency the Owner is usually the only finance holder.
- **Offline benefit already given up.** Cold restart and tab reload required an online unlock; only one tab synchronized.
- **No commercial pull.** `VPS-003` mentioned privacy, encryption or local-first zero times. The E2E promise was also weaker than stated, since a web server delivers the code that holds the keys.

**What replaces it** — `VPS-A003` rewritten: PostgreSQL is canonical; `services/api` is the only writer; named mutations with idempotency and stale-state rejection; Electric replicates each person's permitted Tier 0 slice into device SQLite through sync shapes generated from `VPS-A004`'s policy table; Tier 1 and Tier 2 are field-encrypted under a KMS key hierarchy, fetched on demand, held in memory only, and audited on every read; cryptographic erasure is kept for Tier 1 through per-erasure-domain data keys; Tier 3 is kept as a deferred end-to-end module. Offline: the product now boots offline from cache, reads all Tier 0 data and queues Tier 0 writes.

**What is preserved.** The node and edge registry, privacy classes, tier assignments, the permission matrix and its rules, subject exclusion, k-anonymity, the design system, the CI pipeline, authentication and device trust. The retired implementation — `services/sync-engine`, the Loro Worker runtime and materialization, the sealed store, Tier 1 envelopes, identity transfer and threshold recovery, and the Tier 3 root code — is preserved on branch `archive/local-first-e2e` at `60c2745`. FDN-68's uncommitted audit work at the time of the decision is not on that branch and remains in the founder's working tree.

**Findings this supersedes.** F120 (a Loro document too new to open), F140 (Worker availability states), F141 (local author versus arriving peer) and F186 (per-recipient relay filtering) describe mechanisms that no longer exist; each is closed as superseded, and F186's underlying requirement is now met structurally — Tier 1 and Tier 2 never replicate, and Tier 0 replication is filtered per person by generated streams. F125 (a backdated `managed_by` move) remains open, moved from the Movable Tree to `org.moveEmployee`. F118 (the SyncStatus render) remains open, now with the added `NeedsAttention` state. F127's open question — which channel delivers a live role change — is answered: the sync connection.

**Documents changed:** `CLAUDE.md`, `VPS-002`, `VPS-003`, `VPS-A001`, `VPS-A002`, `VPS-A003` (rewritten), `VPS-A004`, `VPS-A005`, `VPS-A006`, `VPS-A007`, `VPS-F001`, `VPS-F007`. The remaining feature specifications that assume client-side protected processing, the retention window or the Movable Tree are corrected feature by feature under a tracked Linear sweep, each before that feature is built.
