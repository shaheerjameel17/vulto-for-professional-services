### F323 — the two specs disagree on whether successful Tier 2 access is logged

**Found while:** briefing Stage 26 (`VPS-F004`), 26 September 2026, by checking the spec against the code before writing the brief.

`VPS-A004` says every successful grant of Tier 1, Tier 2 or Tier 3 data writes an AuditEntry (its interceptor section), and `VPS-F004` says only Tier 1 and Tier 3 ("Not Tier 0 or Tier 2", G04, Out of Scope). The code follows `VPS-A004`: `authorizeRead` audits any grant with `decision.tier > 0`, and `authorizeWrite` does the same, so a successful Tier 2 access (a manager reading a TimesheetAnomalyFlag, an HR Admin reading a Departure) is already logged today. Both documents are marked decided at founder level; the code and the acceptance criteria are silent on the difference.

**Files:** `docs/Vulto_Specs/VPS-A004_Graph_Permission_Layer.md`, `docs/Vulto_Specs/VPS-F004_Silent_Audit_Log.md`, `services/api/src/permission/interceptor.ts`

**Ruling.** **Closed 26 September 2026 by ruling.** `VPS-A004` and the code stand: successful grants of Tier 1, Tier 2 and Tier 3 are logged, Tier 0 is not. Logging more is the safe direction (an unlogged Tier 2 access cannot be recovered later, an over-logged one can be relaxed by a later decision), Tier 2 records are low-volume (flags, departures, retention signals), and the audit log is itself Tier 2 (see F324). `VPS-F004`'s "What is logged", its overview sentence, G04 and its Out of Scope line are corrected. Recorded so the founder can reverse it if the volume argument matters more to him.
