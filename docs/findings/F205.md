### F205 — the anonymous contribution nodes have no `created_at`, but `graph_nodes` requires one

Raised 21 September 2026, building Stage 2's round-trip test for every registered node type.

**The conflict.** The Stage 2 brief defines `graph_nodes.created_at timestamptz not null`. `VPS-A002`'s universal conventions list a closed set of omissions, and `PulseAggregateContribution` and `WellnessAggregateContribution` omit `created_at`, `created_by`, `updated_at`, `updated_by`, `soft_deleted_at` and `soft_deleted_by`, keeping only `is_soft_deleted`. The omission is deliberate: an exact creation time would let a contribution be matched to the person who submitted it. `records.ts` enforces it, and `VPS-A007` gate 3 tests it. Both types are Tier 0, so they belong in `graph_nodes`.

**Why this was not decided in code.** Putting any value in the column, such as the epoch or the insert time, is either a fabricated fact or the very timestamp the omission exists to withhold. Making the column nullable is the obvious fix, but it changes the schema the brief specified and is a privacy-relevant choice.

**Closed by founder-delegated decision, 21 September 2026.** The recommendation was accepted: `graph_nodes.created_at` is nullable, and a check constraint allows null only for `PulseAggregateContribution` and `WellnessAggregateContribution`, so no other type can omit it. This follows `VPS-A002`'s closed omission policy and keeps those contributions uncorrelatable. Built in migration `0011`; the store no longer refuses the two types, and the round-trip test covers every registered node type.
