### F329 — a policy version has no effective date

**Found while:** briefing Stage 27 (`VRS-F018`), 26 September 2026, by checking the spec against the code before writing the brief.

The spec says a policy update "applies going forward" and that prior accrual is unaffected, but `LeavePolicy`'s schema has no date from which a version applies, so the engine cannot tell which version governs a past month. `RateCard` (Stage 14) solved the same problem with effective dates.

**Files:** `docs/Vulto_Specs/VRS-F018_Leave_Policy_Engine.md`, `services/api/src/mutations/rate-card.ts`

**Ruling.** **Closed 26 September 2026 by ruling.** `LeavePolicy` gains `effective_from` (ISO date). Version 1 defaults to `1900-01-01` (in force for the whole history it can be asked about); an update takes an `effective_from` no earlier than today's UTC date and defaults to it. The engine uses, for each accrual step, the version of the resolved policy lineage in force on that step's date. The spec's schema block is corrected.
