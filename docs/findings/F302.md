### F302 — Do item 8 named a fixture the browser suite never had, and tracing it exposed an unguarded trigger

The F301 correction added Do item 8 to the Stage 23 brief: one assertion in the existing `packages/graph/sync-browser-tests/sync.spec.ts` that a seeded Employee's `cache_search.search_text` contains its lowercased `full_name`. Codex resumed on it, traced the fixture before writing product code, and stopped (`7f87ae6`, finding note and blocked report only). The suite has no such Employee. `seedEntities` (`helpers.ts`) creates only `Entity` nodes through the real `graph.createNode` mutation. `seedProtected` creates an Employee, but through `addNode(tx, workspaceId, "Employee")` in `services/api/src/permission/test-support.ts`, whose record is `nodeRecord`'s universal fields only — no `full_name`, no `job_title`, no `employee_type`. The reviewer wrote item 8 without reading `helpers.ts`; the F301 lesson (read `package.json` and the workflows, not memory) applied equally to the fixtures a test assertion names.

Tracing that fixture also surfaced a hazard in the brief's own trigger design, which is the more important half. That nameless Employee row reaches the device in the existing suite (the role-removal test's `cache_nodes` counts include it), and the brief's Do item 2 has the trigger insert `label` from the registered `labelField` into a `label TEXT NOT NULL` column. A node with no `full_name` would make that insert violate the constraint, the trigger would fail, and a failing trigger aborts `putNode`'s statement — the row would not replicate and the sync engine would see an error, on a device that is otherwise healthy. Nodes without their label field are not a test artefact: `graph.createNode` and future feature mutations can write partial records, and the suite already proves one such row exists.

**Closed by direct precedent — the brief, not the code, was wrong (F259's and F301's own shape), and the browser suite's own header names `services/api/src/test/sync-browser-support.ts` as "what the suite needs from the API's own modules, gathered in one place". No founder consultation needed.** The ruling, in full. (1) The triggers index a node only when its registered `labelField` is a non-empty string — `json_type(record_json, '$.<labelField>') = 'text'` and the extracted value `<> ''` — and treat a non-text value in any other indexed field as absent; a node that fails the guard gets no index row (and any existing row for it is deleted on update), and the trigger has no path that can raise. A nameless node is unsearchable, never an error. Unit tests write a nameless, an empty-named and a non-text-named Employee through `putNode` without error and confirm no row, then a later `putNode` adding a valid name produces one. (2) `seedProtected` creates its Employee with operational Tier 0 fields instead of a nameless one, via `insertNode(tx, { ...nodeRecord("Employee", workspaceId), employee_type: "Employee", full_name: SEARCH_FIXTURE_EMPLOYEE_NAME, job_title: "Search Fixture Engineer" })`, exporting `SEARCH_FIXTURE_EMPLOYEE_NAME` (a fixed constant carrying no Tier 1 or Tier 2 sentinel text); its two existing callers are unaffected, since the Employee is still one row and the seeded counts do not change. (3) The one exception to Stage 23's `services/api/` boundary: `nodeRecord` and `insertNode` are re-exported from `services/api/src/test/sync-browser-support.ts` with exactly one added line for each (`../permission/test-support.js`, `../graph/store.js`), touching nothing else under `services/api/`; `addNode` is not changed and gains no overrides. This is a test-only support module, not product code, and it is the place the suite's own contract says these belong; the alternative — the helper importing API internals by deep path, bypassing that module — was rejected as violating that stated design. (4) The assertions move to the existing role-removal test (it already uses `seedProtected`, reads `dump()` and exercises an Electric move-out through a real role change): after the first `Synced` and again after the role change and audience recompute, poll until `dump()["cache_search"]`'s `node_id` set equals the `node_id` set of non-soft-deleted `cache_nodes` rows of a `SEARCHABLE_NODE_TYPES` type whose registered label field is a non-empty string (polled because replication is eventual and `dump()` reads tables one after another), and at the first point that the Employee's `search_text` contains `SEARCH_FIXTURE_EMPLOYEE_NAME` lowercased. Team Member keeps read of `Employee:operational` (F292), so the Employee is not itself the row that moves out; the second check proves index consistency through the move-out deletes for whatever rows left, and no new scenario is built. The A003-T56 test is unchanged and still scans `cache_search` through `dump()`. F301's clause "(3)… not outside `packages/graph`" is superseded by (3) above.

**Status: closed.**
