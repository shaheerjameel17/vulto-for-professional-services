### F354 — Certifications have no backing data; this is F296, not a new gap

**Found while:** briefing UI-2, 27 September 2026.

`SkillsTab.tsx`'s Certifications list is entirely fixture-sourced (`fixtures/profiles.ts`), and there is no mutation, node type or query anywhere that could produce a real one: `skill-matrix.ts`'s own comment already records `certified: false, // F296: VRS-F041 has not supplied a certification fact yet`, and F296's own ruling closed this exact gap for Skill Matrix — `VRS-F041` (Certification and Training Tracker) is the unbuilt feature that would own it, and no interim mechanism was warranted then for the identical reason it is not warranted now.

**Files:** `apps/roster-web/src/components/profile/SkillsTab.tsx`, `docs/findings/F296.md`, `docs/Vulto_Specs/VRS-F041_Certification_and_Training_Tracker.md`

**Ruling.** **Closed 27 September 2026 by ruling, reusing F296 — no new finding number needed for the underlying fact.** Skills render from the real local skill data (F350/F351's local query, reusing the read path UI-1's skill-match group already established). Certifications render the honest empty state — nothing fabricated, no fixture fallback — until `VRS-F041` exists. `VRS-F002`'s Related Notes gain a one-line pointer to F296 so a future reader of the profile spec finds the existing ruling rather than re-raising it.
