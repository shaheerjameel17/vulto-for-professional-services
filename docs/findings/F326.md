### F326 — most of VPS-F004 is built; the review screen and orchestration are not buildable

**Found while:** briefing Stage 26 (`VPS-F004`), 26 September 2026, by checking the spec against the code before writing the brief.

The rest of `VPS-F004` is either built or not buildable now. Built: the query-layer logging (S01, Stage 3: one `audit` call site in the interceptor, `authorizeRead` and `authorizeWrite`), the closed entry schema with actor kinds and erasure entries (F206, F209), the actor pseudonymization seam (S04, Stage 5: `pseudonymizeActor`, callable only by the `erasure` principal, changing only `actor_user_id`), and the search exclusion (G07, Stage 23). Not buildable: the review screen (S03) needs the shell and `VPS-F005`'s console (unbuilt); `VPS-F007`'s ErasureRequest orchestration that would call the pseudonymizer does not exist.

**Files:** `services/api/src/audit/pseudonymizer.ts`, `apps/roster-web/`, `docs/Vulto_Specs/VPS-F005_Workspace_Configuration_Console.md`, `docs/Vulto_Specs/VPS-F007_Data_Governance_Retention_and_Erasure.md`

**Ruling.** **Closed 26 September 2026 by ruling, on the deferral every prior stage has made.** No UI, no export, no orchestration. The stage confirms by test what the spec's acceptance criteria require of the parts that exist (a denial and a Tier 1 grant write exactly one entry with no content, a Tier 0 read writes none, pseudonymization keeps an erased actor's events correlatable and deletes nothing), adding only the ones the existing suites do not already prove, and measures the logging overhead against the 10 ms non-functional requirement without making it a gate.
