### F349 — the Inbox shows a raw refusal code as the failure reason

**Found while:** the reviewer's read of the UI-1 screenshots, 27 September 2026.

`VPS-F003` says an action failing from the Inbox "states the reason and leaves the item in place". The failure screenshot shows the pipeline's machine code, `not-found`, under the row. A person cannot act on that, and the stated purpose of the state is a reason a person can read.

**Files:** `apps/roster-web/src/app/(shell)/inbox/page.tsx`, `packages/ui/src/InboxRow.tsx`

**Ruling.** **Closed 27 September 2026 by ruling.** The Inbox maps the pipeline's refusal reasons to plain sentences (for example `not-found` to "This item is no longer available", `role` to "You don't have access to do that", `stale-state` to "This item changed. Reload and try again"), with one generic fallback for an unmapped code ("That action could not be completed"); the raw code is never the visible text (it may sit in a `title` or a data attribute for support). The builder enumerates the reasons the three `notification.*` mutations can actually return and maps every one; the browser test asserts the human sentence for the real refusal it already forces.
