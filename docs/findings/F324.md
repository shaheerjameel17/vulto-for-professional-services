### F324 — auditLog.query is unbuilt and its contract is unspecified

**Found while:** briefing Stage 26 (`VPS-F004`), 26 September 2026, by checking the spec against the code before writing the brief.

`auditLog.query`, the feature's only API contract, does not exist (`grep auditLog` in the router and mutation registry is empty; the only reader is `listAuditEntries`, an unfiltered oldest-first dump used by tests), and the spec leaves its shape open: no pagination although the table must "scroll through months", one `eventType` although the review screen's event filter is a Toggle Group, and no statement of what reading the log itself writes to the log. The journal indexes already cover every filter (`occurred_at`, actor, event, target).

**Files:** `docs/Vulto_Specs/VPS-F004_Silent_Audit_Log.md`, `services/api/src/audit/journal.ts`, `services/api/src/router.ts`

**Ruling.** **Closed 26 September 2026 by ruling.** `auditLog.query` is a server-side tRPC query, snake_case like the rest of the router: input `{ workspace_id, start_date?, end_date?, actor_user_id?, event_types? (array, any of), target_node_type?, target_tier?, cursor?, limit? }`, output `{ entries, next_cursor }` with the full `AuditEntry` objects (the row shows everything the entry contains), ordered `occurred_at` descending then `audit_entry_id` descending by keyset pagination on an opaque cursor, limit default 50 and maximum 200. Authorization is the interceptor's own decision for `AuditEntry` (Full for Owner and HR Admin, none for every other role) through `authorizeRead` with a null node id and operation `NodeList`, so a denied caller writes a `PermissionDenied` entry and a permitted call writes one `SensitiveAccessGranted` entry per call (not per row), by the same rule as every other Tier 2 grant (F323); the query reads the page before that entry is appended. Not built: any UI, any export (`VRS-F061`), any device cache.
