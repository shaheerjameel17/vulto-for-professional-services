### F279 — `resolveStoredSubjectEmployeeId` had no branch for `UtilizationSnapshot`

Raised 25 September 2026 by Codex, who traced Stage 19's brief into the existing interceptor before writing any product code and stopped before implementation. F278's ruled Team Member cell on `UtilizationSnapshot` is `Read (own only)`, a row-scoped grant that `rowScopeSatisfied` enforces by calling `resolveStoredSubjectEmployeeId` to find which Employee a given node belongs to. That function's third branch reads a stored `employee_id` field, but only for `nodeType === "TimesheetEntry" || nodeType === "TimesheetWeekSubmission"`; `UtilizationSnapshot` — which stores the identical `employee_id` field per its own Technical Architecture section — was never added, so it falls through to the function's final `return null`. Every `UtilizationSnapshot` read attempted under a Team Member's "own only" grant therefore resolves to no subject at all and is refused, denying a Team Member their own pulse bar entirely — the one read F278's own row was written to guarantee.

**Closed by direct precedent, 25 September 2026.** No founder consultation needed — this branch exists precisely because F268 anticipated further node types storing their subject as a plain `employee_id` field, and `UtilizationSnapshot` is exactly that shape recurring a fourth time (after `TimesheetEntry`, `TimesheetWeekSubmission`, and the field itself). `services/api/src/permission/interceptor.ts`'s `resolveStoredSubjectEmployeeId` third branch is extended:

```ts
if (
  nodeType === "TimesheetEntry" ||
  nodeType === "TimesheetWeekSubmission" ||
  nodeType === "UtilizationSnapshot"
) {
  const node = await getNode(tx, workspaceId, nodeId);
  const employeeId = node?.record["employee_id"];
  return typeof employeeId === "string" ? employeeId : null;
}
```

No other change required.

**Status: closed.**
