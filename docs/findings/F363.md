### F363 — `Claude_Code_Build_Prompt.md` still briefed Codex to run a Linear workflow, after work tracking moved to Notion

**Found while:** Handling the founder's direct instruction (28 September 2026) to stop using Linear entirely and use Notion going forward, for the UI-2 merge follow-up. Checking whether that instruction was already fully applied surfaced a gap: `docs/Reviewer_Role.md` was corrected on 27–28 September ("Work tracking moved from Linear to Notion... Do not create or update Linear issues going forward"), but `docs/Claude_Code_Build_Prompt.md` — the actual brief Codex reads and follows for every stage — was not. Its Part 1 context table still named Linear as the work-tracking system; its Git workflow bullets still said "update Linear" and "set that stage's Linear issues to Done"; and it carried a full "### Linear workflow" section instructing Codex to move issues through In Progress / In Review / Done in Linear and comment findings there, plus a stage-report template line "**Linear issues:** FDN-xx, FDN-yy". Left uncorrected, every future stage boundary would have had Codex touching Linear again regardless of any one-off instruction given elsewhere. `docs/Reviewer_Role.md` also had one stale forward-looking sentence describing Codex as working "via git branches and Linear issues", and another describing a resume prompt carrying "whatever Linear content" the founder needs to paste.

**Files:** `docs/Claude_Code_Build_Prompt.md` (Part 1 context table; Git workflow bullets; the renamed "### Notion workflow" section; the stage-report template's issues line), `docs/Reviewer_Role.md` (two forward-looking sentences).

**Ruling.** **Closed 28 September 2026. Mechanical consistency fix, no founder ruling needed** — this applies the founder's own 27–28 September decision (already implemented in `Reviewer_Role.md`) to the one operative document that had not caught up, rather than deciding anything new. `Claude_Code_Build_Prompt.md`'s work-tracking row now points at the Notion **Vulto Issues (Engineering)** database; its Git workflow bullets say "update the stage's Notion issue(s)" and "set that stage's Notion issue(s) Status to Done"; its Linear workflow section is replaced with a Notion workflow section carrying the same In Progress → In Review → Done discipline and an explicit "do not touch Linear" line; and its stage-report template now asks for "**Notion issues:**". `Reviewer_Role.md`'s two stale sentences are corrected to say Notion. Every *historical* stage entry in both documents that already records what actually happened with Linear (stage-by-stage log entries, past "Linear:" issue citations, the frozen pre-25-September action log) is left exactly as written — it is provenance, not an open instruction, per the same principle F361 applied to the deleted screenshot citations.
