### F341 — the palette's skill-match call has no caller in the web app

**Found while:** briefing UI-1, 27 September 2026.

`skillMatcher.adHocSearch` is a tRPC query on the API (F286), and `apps/roster-web` has no tRPC client (its only server client is Better Auth's). Adding `@trpc/client` for one call is a dependency change for no gain, and the spec (F298) requires this one group to degrade alone.

**Files:** `apps/roster-web/src/lib/auth-client.ts`, `services/api/src/router.ts`, `docs/Vulto_Specs/VPS-F002_Local-First_Search.md`

**Ruling.** **Closed 27 September 2026 by ruling.** A small typed `fetch` in `apps/roster-web/src/lib/` to the existing `/trpc/skillMatcher.adHocSearch` GET endpoint with `credentials: "include"`, no new dependency and no API change. A network failure, timeout, 5xx or 429 shows `requires-connection` with **Retry** for the skill-match group only (F298). A `401` is the one answer `VPS-D004` names as a Reconnect trigger, so it goes through the shell's existing refusal path, not a per-group message; the builder traces how the bootstrap receives an authenticated call's 401 and reuses that path rather than a new one.
