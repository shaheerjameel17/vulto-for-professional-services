### F299 — only four of the spec's seven searchable types can be indexed now, and `search.queryProtected` has nothing to search

The spec's registry table names seven node types, and G05 already states the list is open by design. Checked against the executable registry (`packages/schema/src/registry/nodes.ts`, `protection.ts`): `Employee` (split; `full_name`, `preferred_name` and `job_title` are all in the operational Tier 0 half — `packages/schema/src/employee.ts`), `Skill` (`name`, `category`), `Project` (`name`) and `Client` (`name`) are registered Tier 0 node types, all readable by every role through existing `MATRIX_OVERRIDES` rows (`Project`, `Client`, `Skill`: Team Member `READ_ANY()`), with real rows already reaching devices (`bench-forecast.ts` already reads `Project` `name` and the `belongs_to` edge to `Client`). The other three cannot be registered honestly yet: `Document` carries `inheritedProtection` (its tier follows its parent, so a `file_name` is not uniformly Tier 0 — contradicting the spec's own rule that only Tier 0 identifying fields are ever indexed — and no schema defines a `file_name` field); `Policy` (owner `VRS-F044`) and `Deliverable` (Vulto Projects) have no field schema for the `title` the spec names. Separately, `search.queryProtected` (the server-backed group for matches whose identifying fields are Tier 1, 2 or 3) has no eligible node type: `Contract` and `Departure` are Tier 2 but unbuilt, `Document` is unbuilt, and no built node type has a searchable name above Tier 0.

**Closed by direct precedent — F296's and F248's own forward-dependency pattern, and the spec's own G05, no founder consultation needed.** This stage registers exactly `Employee`, `Skill`, `Project` and `Client`, through a registry (`SEARCHABLE_NODE_TYPES`, `packages/schema`) that refuses at registration any type or field it cannot show to be Tier 0 — including `AuditEntry` by name (G08) — so the structural guarantee (G02) is a property of registration, not of query-time filtering. `Document`, `Policy` and `Deliverable` are recorded as forward dependencies: each is added by the stage that gives it a field schema, by adding one registry entry and bumping the cache version, exactly as G05 describes. `search.queryProtected` and its server endpoint are deferred with them, owned by whichever of `VRS-F020`, `VRS-F022` or `VRS-F023` first builds a node type with a Tier 1–3 name a person may search by, at which point that stage adds the server-backed registry variant and its interceptor-governed, audited endpoint; building an endpoint with zero eligible types now would be a stub with no real caller. The spec's registry table and Decisions Recorded are corrected to say so.

**Status: closed.**
