### F222 — no path creates a workspace's first Entity

Raised 22 September 2026 during the same Stage 11 brief. `VRS-F003`'s G04 states "every workspace has at least one Entity. It cannot be reduced to zero," and its own body says the first Entity is "created automatically during `VPS-F006`'s setup wizard... from the founder's own answers." Checked directly: `VPS-F006` (Workspace Setup and Data Import) has no implementation anywhere in `apps/` or `services/` — there is no setup-wizard route or Entity-creating code path in `services/api/src/auth/workspace-projection.ts` (the module that creates a workspace). `services/api/src/graph/founding.ts`'s `writeFoundingRecords` writes exactly five records on workspace creation — Workspace, the founding User, WorkspaceMembership, and the two membership edges — and no Entity. This is not merely `VRS-F003`'s own gap: `VRS-F002`'s already-built `employeeCreate` mutation (`services/api/src/mutations/employee.ts`) requires a valid, existing `entity_id` and rejects with `invalid-args` when the referenced node is missing or not an `Entity` — so a freshly created workspace, today, cannot create its first Employee either, since it has no Entity to scope one to and no way to make one.

**Ruling — closed 22 September 2026.** Rather than wait for `VPS-F006` (not briefed, no target stage), `writeFoundingRecords` gains a sixth founding record, written in the same transaction as the other five: a default Entity named after the workspace's own name (the same string `createWorkspace` already receives and uses for the `Workspace` node — no new input is asked of anyone), `jurisdiction: "Global"` (the enum's existing catch-all for "no specific employment jurisdiction," never asserting a jurisdiction nobody has confirmed), `default_currency: "USD"` (the most neutral available placeholder; Vulto's stated markets have no single obvious default), `lifecycle_status: "Active"`. All three fields are editable afterward through `entity.update` by an Owner or HR Admin, including before any Employee is created. When `VPS-F006` is eventually built, its setup wizard may ask the founder's own questions and correct these defaults in place — this ruling is the interim bootstrap that keeps G04 true starting now, not a substitute for that wizard. `VRS-F003` is corrected to record this bootstrap path explicitly, since its prior text assumed `VPS-F006` already existed.

**Status: closed.** `services/api/src/graph/founding.ts` and its callers are Stage 11's to update; no `VPS-F006` work is implied or required.
