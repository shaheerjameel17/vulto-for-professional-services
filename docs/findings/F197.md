### F197 — FDN-85's reconciliation log is bespoke, pending FDN-68's audit interface

Recorded as a limitation during FDN-85's Stage 0 ruling, not a defect. Counted like F76, F157 and F185.

FDN-85's done criteria require reconciliation to be "auditable." A typed `AuditEntry` graph node is not available — FDN-53 deferred all audit-node writing to `VPS-F004` (F135), and FDN-68 owns the typed audit interface, which does not exist yet. Building a one-off audit writer inside FDN-85 would repeat the mistake F132 (edge storage), F133 (Gate 2) and F135 (audit writing) were each kept out of their stage to avoid: inventing infrastructure under stage pressure that deserves its own design pass.

So "auditable" here means a **deterministic, replayable structured log** of every reconciliation run and every projection write, each carrying the `privileged-projection-exception` marker that distinguishes it from an ordinary authorized write. **When FDN-68 lands, this log is retrofitted to emit through FDN-68's typed audit interface** rather than staying a permanent bespoke format. Recorded here, and in FDN-85's done-criteria writeback, so the retrofit is not forgotten as "temporary."
