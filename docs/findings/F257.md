### F257 — `VRS-F008`'s "audited per `VPS-F004`" claim has no home in the closed five-value audit taxonomy

Raised 24 September 2026, the identical shape F221, F225 and F252 already ruled on.

**The gap.** `VRS-F008`'s Security Considerations states "Overrides are audited per [[VPS-F004]]." `VPS-F004`'s own closed five-value taxonomy — `PermissionDenied`, `SensitiveAccessGranted`, `AuthorizedOperationFailed`, `PrivilegedProjectionAuthorized`, `CryptographicErasureExecuted` — has no category matching an ordinary, successful, already-authorized Tier-0 write, which is exactly the shape of `conflictResolution.overrideAndProceed`: a caller already permitted to write Assignment (the employee's manager or an Owner, per F255's corrected policy) performing a standard mutation that happens to carry a reason. Inventing a sixth taxonomy value would mean amending `VPS-F004`'s closed enum, which F221 and F225 already ruled against for materially identical claims, and which F252 ruled against for Ghost Resources' promotion.

**Closed by founder-delegated decision, 24 September 2026, on F221/F225/F252's own precedent.** No `appendAudit` call is added for `overrideAndProceed`. The override is fully accounted for by the write itself: `capacity_override_reason`, `capacity_override_by` and `capacity_override_at` are already-scaffolded fields on Assignment (confirmed present and null-initialized in `assignmentCreate`'s `apply()`), visible to anyone who could already see the Assignment per the same Security Considerations section's own second bullet, and covered by `VPS-A002`'s mandatory Universal Node Conventions the same way F252 relied on for Ghost promotion. `VRS-F008`'s Security Considerations bullet is corrected to describe this — the override is recorded on the record itself, not separately audited — matching F221/F225/F252's own corrected wording pattern.

**Status: closed.**
